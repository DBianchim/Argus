## Limites e achado
- **Achado:** o limitador usa `get_remote_address`, e todos os clientes chegam à API pelo Caddy. O log da API mostra as 33 requisições de `/install` desta verificação **e** os `POST /api/v1/ingest` dos agentes remotos vindos do **mesmo endereço ([IP-PROXY])**. Portanto o limite "por IP" é, na prática, **um contador único para toda a frota** (1500/min no ingest). O efeito prático (um flood de um cliente barrando os agentes) não foi testado, por ser disruptivo.
- **Não executado:** limite do `/api/v1/ingest` até o 429 (disruptivo; coberto por teste automatizado `test_rate_limit.py`); expiração real de 12 h (coberta apenas por teste automatizado, com data simulada); bloqueio por tentativas de login (não há mecanismo de bloqueio no código lido).
- **Revogação de token (CT04):** não refeita neste cenário (evidência registrada no CT04).
